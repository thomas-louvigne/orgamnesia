* Projects and pages

** Project
A project is a folder of =.org= pages linked to each other.

- If the folder has a =pages/= subfolder, the pages are there; otherwise, if the
  folder already holds =.org= files, it is used as is. An empty folder gets
  =pages/= and =assets/=.
- *Open or create a folder of notes*: the folder button next to the project name,
  the projects menu or the welcome screen open the system's folder picker, where a
  new folder can also be created; a new or empty folder gets =pages/= and
  =assets/=, then opens. A folder already holding =.org= files is used as it is:
  when it has no =assets/= folder (where the images added to the pages are
  copied), the app offers to make one; declined, it doesn't ask again there.
- The project name, above the list of pages, opens the projects menu: open another
  folder, go back to a recent project, remove a project from the list (the folder
  itself is left untouched).
- Switching projects with unsaved tabs asks for confirmation.
- With no project open, the welcome screen offers to open or create one and lists the
  recent projects.

[[file:images/welcome.png]]

** Pages
- *Create*: the =+= button of the list of pages, the "New page" shortcut, or a right
  click in the list. A new page starts with its title (=* Name=).
- *Open*: click in the list, quick open, or Ctrl+click on a link.
- *Filter*: the "Filter the list…" field above the list of pages keeps the pages
  whose name contains the text typed (ignoring case and accents).
- *Rename*: right click on the page (list or tab), double click on the tab, double
  click or right click on the page title. Links to the page in the other pages are
  rewritten (can be turned off).
- *No export*: right click on the page in the list adds the =:noexport:= tag to
  its =#+FILETAGS:= (the line is created when missing).
- *Delete*: right click on the page (list or tab), last in the menu. The page goes
  to the project's [[*Trash][trash]].

** Quick open
The "Quick open" shortcut (Ctrl+K in Classic, Ctrl+X B or Alt+X in Emacs) opens a
field that searches, ignoring case and accents:
- the open tabs;
- the pages of the project;
- the tags (picking one shows it in the tags frame);
- and offers to create the page when the name typed doesn't exist.

[[file:images/quick-open.png]]

** Saving and outside changes
- Pages are saved on every keystroke (can be turned off); otherwise use the
  "Save" shortcut. An unsaved tab is marked.
- Pages changed or deleted by another program (sync tool, git, another editor)
  are reloaded; the disk is checked every second. When the tab has unsaved
  changes, a dialog asks which version to keep: yours (saved at once with
  autosave) or the one on disk. Escape keeps yours.
- Quitting with unsaved pages asks for confirmation.

** Cleanup on quit
Two settings (off by default) delete on quit:
- empty pages (nothing but spaces, tabs, line breaks or =*=);
- pages holding only their title (=* Name=), like a page created and never filled.

These pages are deleted for good, without going through the trash.

** Session
On start, the tabs and panes open when the app was quit are opened again (can be
turned off).

* Editor

** Org-mode highlighting
- Headlines =*=, =**=… coloured by level, stars dimmed.
- =*bold*=, =/italic/=, =_underline_=, =+strikethrough+= (not inside a word: =1+2+3=
  stays as is).
- Links =[[page]]= and =[[page][text]]=, =#keywords=, =:tags:=.
- =#+TITLE:= and =#+FILETAGS:=: the keyword dimmed, the value highlighted.
- Tables, their header rows in bold.
- TODO keywords (see [[*TODO states][TODO states]]).

** Page title
Above the editor, in large type: the page's =#+TITLE:= if it has one, else its name.
Right click on it: rename the file, add or edit the =#+TITLE:=. Can be hidden in the
settings.

** Folding
Tab folds and unfolds as org-mode's =org-cycle= does. On a headline:
1. folded (everything under it hidden);
2. only its sub-headlines, folded;
3. everything shown.

On a list item with lines under it, a =#+begin_…= block or a drawer
(=:PROPERTIES:= … =:END:=), Tab hides what is under the line, then shows it again.

Shift+Tab out of a table folds the whole page, as org-mode's =S-TAB=: its top
headlines only (OVERVIEW), then all the headlines (CONTENTS), then everything (SHOW
ALL). The "Fold / unfold the whole page" shortcut does the same anywhere
(Ctrl+U Tab in Emacs).

What is folded ends with =…=. On a headline with nothing under it, a message says
so. Backspace or Delete next to the =…= unfolds instead of deleting the hidden
text. Can be turned off (Tab and Shift+Tab out of a table then do what they do
elsewhere).

[[file:images/fold.png]]

** Indentation under headlines
The text under a headline is shifted to the column of the headline's text, like
Emacs' =org-indent-mode=. This is on screen only: the file holds no such spaces.
Can be turned off.

** Headline stars
Optional: only the last star of a headline shows, like Emacs'
=org-hide-leading-stars=; the level reads as an indent.

** Broken links
A link that leads nowhere (a page that doesn't exist, a missing file or image) is
drawn in red, with a ❌ in the margin of its line. On screen only: nothing is written
to the file. Can be turned off.

** Line numbers
Optional, in the margin. They follow the lines of the file, even when a table is
drawn or a headline folded.

** Completion
While typing, a list offers:
- page names after =[[= (accepting closes the link with =]]=);
- page names after =#=;
- existing tags in the tags of a headline (=* Title :pro=), in =#+FILETAGS:= or after
  =:= in the text (accepting adds the closing =:=).

Up and down arrows (or Ctrl+N / Ctrl+P) to choose, Enter or Tab to accept, Escape
(or Ctrl+G) to close. Matching ignores case and accents.

** Pairs and electric mode
- Typing =(=, =[=, ={= or ="= also inserts the closing character.
- Electric mode (on by default): typing =( ) [ ] { } " '= on selected text wraps it in
  the pair.

** Emphasis
Bold, italic, underline and strikethrough by shortcut: on a selection, wraps it in
the markers (or removes them when already there); without a selection, inserts a
pair of markers with the cursor between them.

** New headline
The "New heading" shortcut (Shift+Enter; Alt+Enter in Emacs) inserts, below the
current line, a headline of the same level as the current one. On a list item, as
org-mode's =M-RET=, it inserts a new item instead: same bullet, next number, and an
empty checkbox when the item has one.

** Headline level
On a headline, Alt+Shift+→ moves it one level down and Alt+Shift+← one level up,
together with its sub-headlines, as Emacs' =M-S-<right>= / =M-S-<left>= do
(=org-demote-subtree= / =org-promote-subtree=). A first-level headline doesn't go up.

** Find and replace
- Find in the page: Enter for the next match, Shift+Enter for the previous one,
  Escape to close.
- Replace shows with its own shortcut or the button of the bar: "Replace" (the
  current match) or "All".
- By default, finding ignores case and accents ("regle" finds "Règle"); a button,
  or a setting, makes it exact.
- While finding, tables are shown as text.

*** In the whole project
"Search the project" (Ctrl+Shift+F, =C-x p g= in Emacs) opens a pop-in at the top of
the pane, at the height of the page title. The results come while typing, grouped
by page, with the line around each match; ↑ / ↓ pick one, Enter or a click opens
the page on it. Pages with unsaved changes are searched in their current text.
Options: match case and accents (Aa), whole words (ab).

"Replace in the project" (Ctrl+Shift+H, =C-x p r=) adds the replace field: each match
shows the old and the new text, and checkboxes leave a page or a match out. After
confirmation, the pages with unsaved changes are saved, then the replacement is
made. "Undo", in the status bar or the pop-in, puts the pages of the last
replacement back as they were (but the ones changed since).

[[file:images/find.png]]

** Emacs commands
With the Emacs profile: movements (character, word, line, sentence, paragraph,
headline, start and end of document, page), kill to end of line, kill a word, kill
ring (kill then yank with Ctrl+Y), selection mark.

As in org-mode, a headline is a paragraph of its own: Alt+A / Alt+E (sentence
start / end) stop at it instead of crossing it. In a table, they go from cell to
cell: Alt+E to the end of the cell, then of the next one; Alt+A to its start, then
to the previous one's.

Ctrl+C Ctrl+B / Ctrl+C Ctrl+F go to the previous / next headline of the same level
as the one holding the cursor, without leaving its parent; Ctrl+C Ctrl+U goes up to
the parent headline.

Alt+{ / Alt+} go from element to element, as org-mode's =M-{= / =M-}=: paragraph,
list item, table, block, drawer. On a headline, Alt+} goes past its subtree and
Alt+{ to the previous headline of the same level, or to the parent when there is
none. Ctrl+↑ / Ctrl+↓ remain the paragraph motions.

As in org-mode, the TODO state also turns with Ctrl+C Ctrl+T (=org-todo=).

Ctrl+L (=recenter-top-bottom=) scrolls the page so the line of the cursor is in the
middle of the editor; pressed again, at the top, then at the bottom, then in the
middle again. The cursor doesn't move.

The kill ring follows the system clipboard: what is killed (Ctrl+W, Ctrl+K…) is
copied there, and Ctrl+Y yanks what it holds, even copied in another app. As in
Emacs, kills made one after the other add up: Ctrl+K Ctrl+K Ctrl+K kills three
lines, which Ctrl+Y puts back at once. These
commands work in the other fields of the app too (tags, search, title, commit
message…).

** Moving lines
Alt+↑ / Alt+↓ move the line of the cursor, or the selected lines, up or down. Not
across a folded headline. On a headline, its whole subtree (its text and its
sub-headlines, folded or not) moves past the headline of the same level above or
below it.

*** Selection mark
Ctrl+Space sets a mark: the selection then follows the cursor, like Emacs' region.
Ctrl+Space twice at the same place, or Ctrl+G, cancels it. Killing or copying the
region (Ctrl+W, Alt+W) ends it. Can be turned off.

*** Multi-key shortcuts
Shortcuts can chain several keys (=Ctrl+X Ctrl+S=). The keys typed so far show in
the status bar; Escape cancels, and the sequence is dropped after 4 seconds. Ctrl
can be kept down for the second key (=Ctrl+X Ctrl+O= works as =Ctrl+X O=).

* Links and tags

** Links between pages
- =[[Page]]= or =[[Page][text shown]]=: link to a page.
- =#keyword=: link to the page of that name (can be turned off). Dashes are allowed
  by default (=#my-tag=); unchecked, =#my-tag= is read as =#my=, as org-mode does.
- Ctrl+click, or the "Open link" shortcut (Ctrl+Enter in Classic, Ctrl+C Ctrl+O in
  Emacs), opens the page of the link under the cursor and creates it if needed.
- By default, links ignore case and accents: =[[élody]]= leads to =Elody=.
- "Insert a link" (Ctrl+L in Classic, Ctrl+C Ctrl+L in Emacs, as org-mode) asks
  for its target (the pages are proposed) and the text shown; the selected text
  becomes that text. On a link, it edits it.

** Dates
"Insert a date" (Ctrl+; in Classic, Ctrl+C . in Emacs) asks for a day, today's
first, and a time if wanted, and inserts an org-mode timestamp: =<2026-10-26 Mon>=,
=<2026-10-26 Mon 14:30>=. An active date =<…>= puts the entry in org-mode's agenda;
an inactive one =[…]= (Ctrl+C ! in Emacs, or the box unchecked) only notes when. On
a date, it edits it, keeping what follows the time (a repeater =+1w=…).

** Org-mode tags
- =#+FILETAGS: :a:b:= tags the whole page; =* Title :a:b:= tags a headline (its
  sub-headlines inherit them in the tag search).
- =:example:= in the text is read as a tag too.
- Tags are links to the page of the same name (can be turned off).
- Letters, digits, =_ @ # %= and dashes (=:my-tag:=); dashes can be turned off in
  the settings, to keep only what org-mode reads.

*** Emacs compatibility
Org-mode reads the dashes of =#+FILETAGS: :my-tag:=, but not those of a headline's
tags: =* Title :my-tag:= has no tag for Emacs. To make it read them, add this to
your Emacs configuration (=init.el=), here checked with org 9.8:

#+begin_src emacs-lisp
;; Dashes in org-mode tags (:my-tag:), as Orgamnesia writes them
(with-eval-after-load 'org
  (setq org-tag--valid-char-set "-[:alnum:]_@#%"
        org-tag--invalid-char-re (format "[^%s]" org-tag--valid-char-set)
        org-tag-re (format "[%s]+" org-tag--valid-char-set)
        org-tag--group-enclosed-re (format "\\(:\\([%s:]+\\):\\)" org-tag--valid-char-set)
        org-tag--group-optional-re (concat "\\(?:[ \t]+" org-tag--group-enclosed-re "\\)?[ \t]*$")
        org-tag-group-re (format "[ \t]+%s[ \t]*$" org-tag--group-enclosed-re)
        org-tag-line-re (format "^\\*+ \\(?:.*[ \t]\\)?%s[ \t]*$" org-tag--group-enclosed-re)))
#+end_src

The org files already open must be reopened (or =M-x org-mode= run in them).
The tag searches of Emacs (=C-c a m=, =C-c \=) then find =my-tag= by its name.

** Tag search
In the tags frame, with the org-mode syntax:
- =a+b=: a and b; =a|b=: a or b;
- dashes being allowed in tags, =a-b= is the tag "a-b": write =a -b= to exclude b
  (with dashes turned off, =a-b= is a without b, as in org-mode).

Case matters. The results are the pages (by =#+FILETAGS:=) and the headlines that
match; a click opens the page at the right line. The field completes tag names.

** Adding a tag to the page
The =+= button of the tags frame, or the "Add a tag to the page" shortcut
(Ctrl+Shift+T, =C-c C-q= in Emacs), which opens the field at the top of the pane
even without the frame: the tag goes in =#+FILETAGS:=, with the tags of the
project completed.

* TODO states
As in org-mode, a keyword after the stars of a headline gives its state.

[[file:images/todo-states.png]]

- *Change the state*: on a headline line, wherever the cursor is, "Next TODO state" /
  "Previous TODO state" go through (none) → TODO → DOING → HANGUP → DONE → (none).
  Default shortcuts: Shift+→ and Shift+← in the Emacs profile, none in the Classic
  profile (set them in the settings). Off a headline, the shortcut does what it
  usually does (Shift+arrows select).
- *Display*: states in progress in red, done states in green; a done headline is
  dimmed.
- *List of states*: in the settings, in the Emacs format =TODO DOING HANGUP | DONE=.
  The states after the =|= are the done ones; without =|=, only the last one is.
  Emacs suffixes (=TODO(t)=, =DONE(d!)=) are accepted and ignored.
- *Per page*: a =#+TODO:= line (or =#+SEQ_TODO:=, =#+TYP_TODO:=) gives the page its own
  states. Several lines make several sequences: the cycle stays in the sequence of
  the current keyword.
- *Overview*: the "To do" frame (right column by default).
- The whole feature can be turned off in the settings.

* Tables
- An org table (=| a | b |=) is drawn as a real table while the cursor is not in it;
  it turns back into text to be edited.
- Tab and Shift+Tab move to the next or previous cell and align the table again, as
  org-mode does. Tab after the last cell adds a row.
- =|-= then Tab draws the separator line; the rows above the first separator are the
  header.

[[file:images/table.png]]

* Images
- A line holding only a link to an image (=[[../assets/photo.png]]=, maybe after the
  stars of a headline or a list dash) is drawn as the image while the cursor is not
  on it; it turns back into text to be edited.
- The button at the bottom right of the editor, "Insert an image…" in the
  right-click menu, or dropping a file on the page, copies the image into the
  project's =assets/= folder, named as Logseq names them
  (=photo_1759520598218_0.png=), and adds its link on a line of its own.
- "Import a file…" in the right-click menu (or dropping it on the page) does the
  same with any file (PDF, document…), linked by its name:
  =[[../assets/report_1759520598218_0.pdf][report.pdf]]=. Ctrl+click on the link
  opens it with the system's application; programs and launchers are never run.
  Ctrl+click on a web link opens it in the browser.
- The bottom right corner of an image resizes it with the mouse. The size is written
  in the org-mode format (=#+ATTR_ORG: :width 300= on the line above, the default) or
  the Logseq one (={:height 200, :width 300}= after the link). Both are read; Logseq
  adds one at each resize, the last one counts.
- Can be turned off: the links then stay text.

** YouTube videos
A video is linked like any web page, with a plain org-mode link, which every tool
reads (Emacs, Logseq, GitHub…):

#+begin_src org
[[https://www.youtube.com/watch?v=dQw4w9WgXcQ]]
#+end_src

Alone on its line (maybe after headline stars or a list dash), the link is drawn as
the video's thumbnail, with a play button, while the cursor is not on it; a click
opens the video in the browser. The thumbnail is downloaded from YouTube (shown as
text offline), and is resized like an image. =youtube.com/watch?v==, =youtu.be/=,
=/shorts/= and =/embed/= addresses are recognized; a link with a description
(=[[url][title]]=) stays a link. Can be turned off in Settings > Display.

Logseq's ={{video url}}= macro (or ={{youtube url}}=) is read too, but marked: a
red cross at the bottom left of its thumbnail, and a message saying to use the
link instead, which Emacs and other tools read. A click on the cross replaces the
macro with the link.

* Window

** Tabs
Each pane has its own tabs. Click to activate, double click to rename the page,
right click to rename or delete, =×= to close.

** Two panes
Like Emacs windows: split the editor side by side or one above the other, move to
the other pane, close the current pane or keep only it. A page must be open to
split. With a single pane, closing the pane closes the tab.

[[file:images/split.png]]

** Page history
"Back to previous page" and "Forward to next page" (Alt+← and Alt+→) go through the
pages shown in the pane, like a web browser.

** Window regions
F6 and Shift+F6 move between the left column, the editor and the right column. Lists can be
browsed with the keyboard.

** Empty editor
With no page open: a button to go to a page and the essential shortcuts.

** Status bar
At the bottom of the window: messages (page saved, error, keys of a shortcut being
typed…). After a deletion, it offers "Undo". =×= closes it.

* Left and right columns
The editor stands between two columns of frames. In Settings > Display, each frame
can be shown or hidden, and its arrows put it above or below another frame, or in
the other column: app name and logo, open project, git state, pages menu, Settings
button, quit button, org-bloom button, backlinks, tags, to do, pages not created. A
column with no frame shown goes away. Their width can be changed with the mouse. By
default, on the left: name, project, git, org-bloom, pages, Settings; on the right:
quit, backlinks, tags, to do, pages not created.

[[file:images/side-panel.png]]

- *Backlinks*: the pages linking to the page shown.
- *Tags*: every tag of the project with its count, and the tag search. The =+= of the
  header adds a tag to the page shown (in =#+FILETAGS:=); the =+= of a tag in the list
  adds that one directly.
- *To do*: the TODO headlines of the whole project, by page. The filter shows the
  headlines in progress (default), done, all, or a single state. A click opens the
  page on the headline.
- *Pages not created*: links to pages that don't exist, most used first. Click:
  visits in turn the pages using the link; right click: create the page, or go to
  the link in a given page. With another list in its column, its height can be
  changed with the mouse; alone, it fills the column.

* Trash
- A deleted page goes to the project's =.trash/= folder, named =<time>-<page>.org=.
  The folder holds a =.gitignore= that keeps it out of git.
- Deleting asks for confirmation (red button, focus on Cancel: Enter doesn't
  delete).
- Right after, "Undo" in the status bar puts the page back and reopens it if it was
  open. If a page of the same name was created in the meantime, restoring is
  refused.
- Settings > Editing > Trash:
  - the number of pages in the trash and an "Empty the trash" button (for good,
    with confirmation);
  - "Empty the trash automatically" (off by default): when a project opens,
    deletes the pages kept longer than the chosen time (30 days by default), then
    the oldest ones while the trash is over the maximum size (10,000,000 bytes by
    default). 0 = no limit for that criterion.
- The age of a page comes from the time in its name. A file dropped there by hand
  without that prefix counts as just deleted.

* Keyboard shortcuts

** Profiles
Two built-in profiles, *Classic* and *Emacs*, apply to the whole application.
Changing a shortcut creates a custom profile (which can be renamed, duplicated,
deleted). Each action takes two shortcuts. A conflict (the same keys for two
actions) is shown and prevents saving.

The built-in profiles are in the application and can't be changed: changing one
of their shortcuts copies them into a custom profile, which takes effect. Each
custom profile is a file of its own, named after it (=keybindings/Personnalisé.json=
by default), which can be edited as text (see [[*Settings as text]]).

Built-in profiles get the new shortcuts of later versions automatically; a custom
profile gets those of the actions it didn't know.

| Kill next / previous word      | —                   | Alt+D / Alt+Backspace         |
| Delete next character          | —                   | Ctrl+D                        |

In Classic, movement and selection stay those of the system (arrows, Home, End,
Shift+arrows…). In a profile, the browser's editing shortcuts that are not assigned
(for example Ctrl+C in Emacs) do nothing.

* Extensions

** Git
Needs git installed. On by default; turned off in Settings > Extensions.

[[file:images/git-status.png]]

*** State of the project
Under the project name: its branch and what is left to commit, push or pull ("Up to
date", "no remote branch", "no remote repository", "detached"…), the files in
conflict and a merge in progress. The state is updated when the repository changes.
The remote is fetched (=git fetch=) when the project opens, then every 5 minutes, so
that the commits to pull are counted; offline, it simply fails until the next time.
The interval is set in Settings > Extensions (0: never fetched; the commits to pull
are then counted as of the last pull).

In the pages list, a small ↑ marks the pages that differ from the remote branch:
changed, or committed and not pushed yet. Without a remote branch, those changed
since the last commit. It can be turned off in Settings > Extensions.

A click on "⚠ N in conflict" opens a page in conflict (the next one at each click),
the cursor on its first =<<<<<<<= marker. Keep what you want, remove the markers and
save: the page is marked resolved (=git add=) and the count goes down; also when it
is fixed in another editor. A merge is then concluded with Commit; a rebase, in a
terminal (=git rebase --continue=).

When git can't read the folder (for example a folder belonging to another user,
"dubious ownership"), the frame says so, with what to do.

*** Commit, pull, push
Three buttons under the state; their shortcuts are in Settings > Shortcuts
(Classic: Ctrl+Shift+G, Ctrl+Shift+U, Ctrl+Shift+P; Emacs: =C-x g c c=,
=C-x g F p=, =C-x g P p=). Unsaved pages are saved first. Push shows the number of
commits to push; a branch with no remote branch yet is pushed to =origin= and set to
track it.

- *Commit* opens a window listing the files changed, each with a box: only the files
  ticked are committed. A click on a file shows what changed in it. The message
  proposed lists the files ticked, and follows them until you type in it.
  Ctrl+Enter does what the main button does (=C-c C-c= in Emacs), Escape cancels
  (=C-c C-k=). "Commit and push" pushes right after. With "Commit and push by
  default", the main button is "Commit and push", the other "Commit only".
- The message proposed can come from a template (Settings > Extensions):
  ={date}=, ={time}=, ={count}= and ={files}= are replaced, for example
  =Notes {date} ({count} files)=. Empty: a summary and the list of the files.
- *Pull* puts the changes not committed aside meanwhile, then back
  (=--autostash=). When the history diverged from the remote, your commits are
  replayed on the remote's (=--rebase=); with "Pull: rebase a diverged history" off,
  the pull only moves forward and is refused then. When both change the same lines, nothing is
  changed: the app never resolves conflicts, it tells you to merge in a terminal or
  a git tool.
- The common errors come with what to do: SSH key, https identifiers, name and email
  of git, push refused because the remote has new commits…
- Pull and push never ask a question: ssh runs in batch mode. A key with a
  passphrase must be loaded in =ssh-agent=; the key to use can be set in
  Settings > Extensions (empty: the system's SSH setup). An =https://= remote needs
  a credential helper.

*** History of a page
"Git history…" in the right-click menu of a tab or of a page of the pages list: the
commits that changed the page, newest first, following its renames. For each, what
it changed, or the page as it was then. "Restore this version" puts it back: in its
tab when the page is open (the editor's undo takes it back), else on disk, after
confirmation.

*** Automatic sync
Settings > Extensions > "Sync automatically every (minutes)": every so many minutes,
the changes are committed with the proposed message, then pulled and pushed. Quiet
when there is nothing to do. "Also sync on quitting" does the same when quitting the
app (with the Quit button or its shortcut), whatever the interval. It stops at the first failure (a conflict…), said in the status bar,
and starts again after a pull or a push that works, or in another project; on
quitting, the app asks whether to quit all the same. 0 (the default): never.

*** Setting up
- A project that is not a repository: "Create a repository" in the git frame runs
  =git init= and writes a =.gitignore= for the editors' backups (=*~=, =#*#=…).
- A repository without a remote: "Add a remote repository…" asks for its address
  (an empty repository made on GitHub, GitLab…), which becomes =origin=; the first
  push sends the branch there.
- "Clone a git repository…", in the projects menu and on the welcome screen: the
  repository is cloned into a new folder named after it, in the folder chosen, then
  opened as the project. The SSH key of the settings is used.

** org-bloom: the site of the project
[[https://github.com/thomas-louvigne/org-bloom][org-bloom]] (formerly logseq-site-builder) turns the project into a static
website. Off by default. When on, an "org-bloom" button (placed like the other frames,
in Settings > Display) saves the pages, then runs =org-bloom build <project>=; the
status bar shows the folder of the site, or what went wrong.

- The site goes to the =output_dir= of the =[site]= table of =org-bloom.toml=, at the
  root of the project (created by the first build). This folder is wiped on every
  build. Settings > Extensions shows this folder, read from the file; a click opens
  it in the file manager.
- "Also zip the site": org-bloom then puts the site in =<folder>.zip=, beside it
  (=--zip=).
- "Disable external dependencies" (off by default): org-bloom leaves out the
  =external_static_dirs= and the =pages/= subfolders holding HTML; links to them
  lead to the 404 page (=--no-external-deps=).
- The command can be set; empty, =org-bloom= is looked for on the PATH, then in
  =~/.local/bin= (an app started from the menu may not have it on its PATH).

** Spelling
Words the dictionary doesn't know are underlined in red. On by default: turn it off
in Settings > Spelling, which also tells how to install a dictionary when none is found.

- *Dictionaries*: the Hunspell ones of the system (on Linux, the =hunspell-fr=,
  =hunspell-en-us=… packages; LibreOffice's on macOS), or a folder of =.aff= +
  =.dic= files chosen in the settings, looked in first. The dictionary is the
  interface language's by default, or the one picked in the settings.
- *Left out*: code, links, tags, and words with digits or capitals.
- *Right click* on an underlined word: suggestions, and "Add to the dictionary".
  Your own words are kept in =dictionary.txt=, in the settings folder.
- *Next misspelled word*: F7 in Classic, Ctrl+, in Emacs (as =flyspell-goto-next-error=).

without closing (a dot shows there are some), "Save" saves and closes, "Cancel"
closes without saving. The explanations under a setting are in italics.

** Shortcuts
Profile, shortcuts of the application, the panes, the editor, the selection mark
(with its setting) and the TODO states (with their setting). A field on top
filters the actions by name or shortcut.

* Settings as text
"Edit the settings as text", at the bottom of the settings window, opens the
*preference* project: the configuration files in the editor, in place of the open
project. This project is always in the projects menu; "← <project>", above the
file, goes back to the project left, its tabs and panes as they were.

- *Its pages*: =settings.json= (the settings, and =keybinding_profile=, the
  shortcuts profile in effect: =classic=, =emacs= or the name of a custom one),
  then a =keybindings/<name>.json= file per custom profile (its base preset, the
  shortcuts of the application and of the editor). From the Shortcuts tab, the
  link opens the file of the profile in effect.
- *JSON highlighting*: keys, strings, numbers, =true= / =false= / =null=. Tab and
  Shift+Tab indent and unindent by two spaces (the selected lines when there is a
  selection).
- *Checked as you type*: the bar above the file says "Valid file", or what is wrong
  and where ("Line 3, column 5: …"), underlined in the text; a click on the message
  puts the cursor there. Refused: invalid JSON, a value of the wrong type, an
  unknown key (a typo), a profile that doesn't exist, a shortcut given to two
  actions, a file named after a built-in profile. An unknown action is only a
  warning.
- *Apply* (or the Save shortcut) writes the file and puts it in effect, only when
  it is valid. These files are never saved automatically.
- *Going back*: "Back to the last valid version" drops the changes not applied;
  "History" lists the last 10 valid versions of the file, each can be put back.
- *Changed outside the app* (with Emacs…): a valid file is put in effect at once;
  an invalid one is not, the previous configuration stays, and a dialog offers to
  correct it or to go back to the last valid version. The same dialog shows on
  start for a file found invalid.

* Files
- Pages stay plain =.org= files, readable and editable with Emacs or any other
  editor.
- Settings: =~/.config/com.orgamnesia.app/=: =settings.json= (the settings),
  =keybindings/= (the custom shortcut profiles), =state.json= (what the app keeps
  for itself: the open project, the projects, the pages open on quit),
  =history/= (the previous valid versions of the configuration files) and
  =dictionary.txt= (the words added to the dictionary).
- Trash: =<project>/.trash/=.
